## Known Issues / Caveats

### 1. Four specs are already built under mismatched directory names

The extractor reported **0 already-implemented**, but four chapters embed
working `<iframe>` sims whose built directory name does not match the spec's
`sim-id`. As a result, these four were written as TODO files even though a
runnable sim already exists:

| Built directory (has `main.html`) | TODO file created |
|-----------------------------------|-------------------|
| `ai-ml-taxonomy` | `ai-ml-taxonomy-healthcare.json` |
| `encounter-workflow` | `clinical-encounter-workflow-diagram.json` |
| `healthcare-graph-fundamentals` | `basic-healthcare-graph-model-diagram.json` |
| `query-performance-comparison` | `query-performance-comparison-chart-rdbms-vs-graph-database.json` |

**Effective unimplemented count: ~87** (91 minus these 4 duplicates).

**Recommended fix:** align each of these four spec `sim-id` fields to the built
directory name (their iframes already use the built name), then re-run the
extractor so they are correctly skipped — or delete the four redundant TODO
files.

### 2. `bloom_level` field is null

The extractor populates `bloom_level` / `bloom_verb` only when a spec has a
dedicated `Bloom:` line. This book's specs encode the Bloom level inline in the
`learning_objective` (e.g., "Analyze (L4 — differentiate, compare) ...") and in
the full `specification`, so the dedicated `bloom_level` field is `null` in all
91 files. The information is still present in the objective text.
